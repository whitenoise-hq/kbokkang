# 크보깡 — 앱 기획서 (Expo + React Native)

> 위치: `kbokkang/apps/mobile` (Expo + RN). 공통 코드는 `@kbokkang/shared` 사용.
> `00_통합기획서.md`의 공통 규칙을 전제로 한다. 데이터·포인트·확률은 통합기획서 참조.
> 개발 순서상 어드민(`01`) 및 크롤링/정산 구축 이후에 개발.
> 앱도 **화면(UI)을 먼저 만들고 데이터 연결은 그 다음**에 한다(통합기획서 2장).
> 디자인은 `04_앱디자인가이드.md` 토큰을 반드시 사용.

---

## 1. 목적

유저가 매일 경기를 예측하고, 포인트로 카드를 뽑아 도감을 채우는 핵심 경험을 제공.

## 2. 기술

- Expo + React Native.
- Supabase 클라이언트(Auth, DB, Storage 읽기).
- 뽑기/정산 등 검증 필요한 로직은 클라이언트 신뢰 금지 → 서버(RLS/함수)에서 처리.

---

## 3. 화면 구성 (하단 탭 5개)

### 탭 구성

1. 홈(예측) — **당일 경기만**
2. 예측 — 지난 예측 목록 + 성적(적중률·연승·스코어 적중)
3. 뽑기
4. 도감
5. 마이

> **왜 예측 탭을 분리했나:** 홈에 어제 결과 카드를 함께 나열하면 "오늘 예측"이라는 초점이
> 흐려지고 스크롤이 길어진다("한 화면 한 핵심 행동"). 지난 예측은 조회·기록 성격이라
> 적중률·연승 같은 성적과 함께 보는 게 자연스럽다.
>
> 그래서 **3.5(마이)에 있던 성적 항목이 예측 탭으로 옮겨왔다.** 마이는 계정·포인트·설정에
> 집중한다. 두 곳에 성적을 두면 중복이 된다.
>
> 다만 홈 상단에 **어제 결과 한 줄 배너**를 둔다 — 예측 앱을 여는 가장 큰 동기가
> "내가 맞췄나?" 인데 예측 탭에만 두면 확인 경로가 한 단계 늘어난다.
> 탭하면 예측 탭으로 간다. 적중이 있으면 초록, 없으면 중립(흰색 + 진한 테두리)이다 —
> 실패를 빨강으로 강조하면 앱을 열 때마다 기분이 나빠진다.
>
> 탭 5개는 **모두 같은 형태**다. 뽑기를 중앙 원형 버튼으로 강조해봤지만 혼자 튀어나와
> 열이 맞지 않아 버렸다. 디자인 가이드 7.1 의 "뽑기만 화려하다"는 **뽑기 화면**에 대한
> 것이고 탭 바(내비게이션 크롬)가 아니다.

### 3.1 온보딩 / 인증

- 회원가입/로그인(Supabase Auth: 이메일/OAuth).
- **최초 1회 온보딩: 닉네임 + 응원팀 선택**(구단 로고+컬러 표시, teams 테이블).
  - 가입 폼에서 닉네임을 받지 않는다 — OAuth 는 가입 폼이 없어서 물어볼 화면이 없다.
  - 프로필 행은 가입 트리거가 만들고 `nickname is null` 이다.
    **앱은 `nickname is null` 이면 온보딩으로 보낸다.**
  - 닉네임 규칙(2~12자, 한글·영문·숫자, 대소문자 무시 유일)은 통합기획서 5장 참조.
    검증은 `@kbokkang/shared` 의 `nicknameSchema`, 중복 확인은 `is_nickname_available` RPC.
  - 중복 확인 후 저장까지의 경합이 있을 수 있으므로 **unique 위반 에러도 처리**해야 한다.
- 가입 시 200포인트 지급(트리거에서 `point_transactions` 기록까지).
- **닉네임은 설정(3.5)에서 수정 가능.** 온보딩과 같은 스키마(`profileUpdateSchema`)를 쓴다.

### 3.2 홈 (예측) ★핵심

- **당일 경기만** 카드로 나열(최대 5경기). 지난 날짜는 예측 탭이 담당한다.
- 각 경기: 홈/원정 팀(로고·컬러), 시작 시각, 예측 마감까지 남은 시간, 현재 status.
- 카드 구조: **3열(원정 / 무승부 / 홈)이고 셀 자체가 선택지다.**
  - 팀 마크와 이름을 한 셀에 가로로 두고 바깥쪽 끝에 붙인다. 무승부 칸은 좁게.
  - **정산 후에는 무승부 칸에 스코어가 들어간다.** 이때 "무승부" 글자는 실제로 무승부일
    때만 남긴다 — 홈/원정이 이긴 경기에 붙어 있으면 결과를 잘못 읽는다.
  - 적중한 셀(정산 후)은 초록으로 강조한다.
- 예측 입력:
  - 승패 선택(**홈 / 무승부 / 원정 3택**) — 필수
  - **스코어 예측 입력은 보류.** 아래 4장 참고.
  - 마감(**start_at - 30분**) 전까지만 가능. 마감 후 UI 잠금.
  - **저장은 명시적이다** — 선택만으로 저장하지 않고 **경기 카드마다 저장 버튼**이 나타난다
    (고른 값이 저장된 값과 다를 때만). 선택할 때마다 요청이 나가면 낭비다.
    화면 하단 일괄 저장은 택하지 않았다 — **경기마다 마감 시각이 다르고**(일요일은 14:00·17:00),
    저장 전에 앱을 닫으면 선택이 사라진다.
- 상태 표시: 예측함 / 마감 / 경기중 / **집계중** / 정산완료(적중·획득 포인트).
- 지난 예측 히스토리(적중률, 연승 등) 접근.

### 3.3 뽑기

- 보유 포인트 표시.
- 뽑기 2종:
  - 일반 뽑기 (100p / 1회, 950p / 10연차)
  - 프리미엄 뽑기 (300p / 1회, 2850p / 10연차) — 상위 등급 확률↑
- 1장 / 10장 버튼. 포인트 부족 시 비활성.
- 뽑기 연출:
  - 결과 카드 공개. 등급별 색/이펙트.
  - **레전드·신화: 반짝임 모션**(이미지 위 코드 오버레이) + 특별 연출.
  - **중복 시: 우상단 "보유" 배지.** 자동 환급이 아니다 — 카드로 쌓이고(`count+1`)
    결과 화면 하단의 **`여분 N장 판매 · +XP`** 버튼으로 한 번에 팔 수 있다.
    이유는 통합기획서 6장 "자동 중복 환급은 폐지했다" 참고.
- 10연차 보장 규칙 반영(프리미엄: 최소 1장 에픽↑) _[초안]_.

### 3.4 도감

- 전체 카드 그리드. 미보유는 실루엣/잠금 표시(수집욕 자극).
- 필터: 등급별(N/R/E/L/M), 종류별(선수/마스코트/아이템).
- 진행률: 전체 및 등급별(예: 에픽 12/30).
- 카드 상세: 이미지(통이미지) + 코드로 이름·도감번호·등급 표시. 보유 수량.
  - 여분 있으면 **판매 버튼**(등급별 고정가) — **여분 전부를 한 번에** 판다.
    한 장씩 팔면 여분 3장에 세 번을 눌러야 하고, 가격이 등급 고정이라 나눠 팔 이유가 없다.
  - 마지막 1장은 판매 불가. 비활성 버튼 아래에 **이유를 함께** 쓴다.
  - 미보유 카드도 열린다. 등급·종류만 보여주고 **이름은 `???`** — 채우는 재미를 남긴다.

### 3.5 마이

- 프로필: 닉네임, 응원팀, 보유 포인트.
- ⚠️ **성적은 여기 두지 않는다.** 위 탭 구성에서 적었듯 적중률·연승은 **예측 탭**이 담당한다 —
  두 곳에 두면 같은 숫자를 두 번 보여주고 계산이 갈라질 위험도 생긴다.
  성적 정의는 4장, 계산은 `@kbokkang/shared` 의 `record.ts` 한 곳이다.
- 포인트 내역(획득/사용). 사유 문구는 `POINT_REASON_LABEL`(shared) — 어드민과 같은 문구여야
  운영자와 유저가 같은 내역을 본다.
  - **차감을 빨강으로 쓰지 않는다.** 뽑기로 포인트를 쓰는 것은 실패가 아니라 정상 행동이고,
    내역이 빨간 줄로 가득하면 잘못한 것처럼 보인다. 구분은 부호(`+`/`−`)가 하고 획득만
    `success` 로 강조한다.
- 설정: **닉네임 변경**, 응원팀 변경, 로그아웃, **회원 탈퇴**.
  - **회원 탈퇴는 App Store 심사 지침 5.1.1(v) 필수**다. 계정을 만들 수 있는 앱은 앱 안에서
    계정을 삭제할 수단을 제공해야 한다 — 없으면 리젝된다. 지우지 말 것.
  - 응원팀 변경 화면은 **온보딩과 같은 화면을 쓴다**(10팀 2열 격자).
  - 닉네임 변경은 온보딩과 동일한 검증·중복 확인을 거친다(`profileUpdateSchema`).
  - 수정 가능 컬럼은 DB 에서 컬럼 단위 grant 로 제한된다
    (`nickname`, `favorite_team_id` 만. 포인트는 서버에서만 변경).

## 4. 핵심 규칙 (앱 관점)

### 예측

- 마감 판정은 **서버 시각** 기준. 클라이언트 시각 신뢰 금지.
  - 앱은 `useServerNow()` 로 보정된 시각을 쓰고, 단계 판정은 `gamePhaseOf`(shared) 한 곳에서 한다.
  - 서버 측 방어선은 `predictions_insert_own` RLS 정책(`now() < g.predict_close_at`)이다.
- 마감(**시작 30분 전**) 후 예측/수정 불가.
- **스코어 예측 입력은 보류다(앱은 항상 null 을 보낸다).**
  - 바텀시트 + 스텝퍼로 만들어 봤지만 걷어냈다. 야구 정확 스코어는 적중이 사실상 나지
    않아 150P 보상이 거의 발생하지 않는데, 시트 애니메이션·스텝퍼·"승무패와 스코어가
    어긋나면 무엇이 맞나" 규칙까지 복잡도가 컸다. 핵심 루프는 승패만으로 완결된다.
  - **DB·정산·스키마는 그대로 둔다** — `predictions.pick_home_score`/`pick_away_score`,
    `prediction_result = 'score_hit'`, `point_transactions.reason = 'predict_score'`,
    `POINT_REWARD.predictScore`(150). 켤 때 **마이그레이션 없이 화면만** 붙이면 된다.
- **무승부도 선택지다**(홈/무승부/원정 3택). 무승부를 고른 사람이 적중한다 —
  KBO 는 무승부가 실제로 있어서(실측 3:3, 0:0) 2택이면 그 경기 예측자 전원이 손해를 본다.

### 성적 (적중률·연승)

계산은 `@kbokkang/shared` 의 `record.ts` **한 곳**에 있다. 앱(예측 탭)과 어드민(유저 상세)이
같은 숫자를 보여야 한다 — 두 곳에서 따로 세면 운영자가 유저와 다른 성적을 본다.

- **`pending`(정산 전)과 `void`(취소 무효)는 성적에 넣지 않는다.** 분모에 넣으면 경기 종료
  직후 적중률이 떨어져 보이고, 비가 왔다고 기록이 깎인다.
- **적중률** = 적중 / 확정된 예측. 확정된 예측이 0 이면 `0%` 가 아니라 **`–`** 로 표시한다
  (신규 유저에게 실패한 것처럼 보인다).
- **연승은 하루 단위 "그날 전승"** 이다. 그날 확정된 예측을 **전부** 맞힌 날이 며칠 연속인가.
  - 그날 하나라도 틀리면 끊긴다. 5경기 중 4경기를 맞혀도 전승이 아니다.
  - 확정된 예측이 없는 날(전부 취소·집계중)과 **예측하지 않은 날은 끊지 않고 건너뛴다.**
    하루 앱을 안 열었다고 기록이 사라지면 안 된다(예측은 무료다).
  - 화면 표시 단위는 **"일"** 이다(`최고 연승 3일`). `3연승` 으로 쓰면 3경기로 읽힌다.
  - ⚠️ 처음엔 **경기 단위**(연속 적중 경기 수)였는데 버렸다. **평일 KBO 5경기는 전부
    18:30 시작**이라 시작 시각으로 순서가 정해지지 않는다. 그러면 같은 데이터에서
    `적중 미적중 적중 적중 적중` 은 3, `적중 적중 적중 적중 미적중` 은 4 가 되어
    **DB 반환 순서에 성적이 좌우됐다**(어드민 쿼리에 `ORDER BY` 도 없었다).
    하루 단위는 이 문제가 원인부터 사라지고, 유저가 날짜별 목록만 보고 검산할 수 있다.

### 정산 (앱은 결과만 표시)

- 서버(**Supabase Cron + Edge Function** + DB)가 경기 종료 감지 후 정산.
- 앱은 predictions.result / earned_points를 읽어 표시.
- 정산 전 종료 경기는 "집계 중"으로 안내(포인트 미지급 오해 방지).

### 포인트 (통합기획서 6장)

- 수급: 가입 200 / **승패·무승부 적중 30** / 스코어 150.
- 소비: 일반 100 / 프리미엄 300.
- 판매/환급: N5 R10 E15 L20 M30.
- 모든 포인트 변동은 point_transactions에 기록.

### 뽑기 (통합기획서 6장 확률)

- 서버에서 확률 추첨 처리(클라 조작 방지). 결과만 앱에 반환.
- 등급 확정 → 등급 내 draw_weight 비례 카드 선택 → user_cards 반영 → 중복 시 환급.

## 5. IP/에셋 주의

- 카드 이미지: 오리지널만(실존 선수/구단 로고/유니폼 금지).
- 응원팀 로고: teams.logo_url(별도, 동우 판단하에 사용).
- 카드 텍스트(이름/번호/등급)는 이미지가 아니라 코드로 렌더.
- 반짝임 모션: 레전드/신화만 코드 오버레이.
