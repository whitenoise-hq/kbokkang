# 크보깡 — 앱 디자인 가이드 (토스 스타일)

> `apps/mobile`(Expo + RN)의 디자인 시스템. 어드민(`apps/admin`)은 shadcn/ui 사용, 이 가이드 대상 아님.
> **핵심 원칙: 모든 화면은 아래 디자인 토큰을 사용한다. 화면마다 즉흥적으로 스타일을 정하지 않는다.**
> 토큰은 `packages/shared`(또는 `apps/mobile/theme`)에 정의하고 전 화면에서 참조.

---

## 0. 토스 스타일 핵심 원칙
1. **넉넉한 여백.** 요소끼리 붙이지 않는다. 숨 쉬는 공간.
2. **한 화면 = 한 핵심 행동.** 복잡하면 단계로 쪼갠다(스텝 플로우).
3. **큼직하고 명확한 타이포.** 특히 숫자(포인트)는 크고 시원하게.
4. **절제된 색.** 무채색(화이트/그레이) 기반 + 포인트 컬러(파랑) 최소 사용.
5. **부드러움.** 둥근 모서리, 은은한 그림자, 부드러운 애니메이션.
6. **명확한 위계.** 제목 / 본문 / 보조 텍스트가 크기·색으로 확실히 구분.

### 테마 모드 — **라이트 고정**

`app.json` 의 `userInterfaceStyle: "light"`. 다크모드는 지원하지 않는다.

이유: 카드 이미지와 5개 등급색이 어두운 배경에서도 사는지 전부 재검수해야 하므로 색 관리
비용이 두 배가 된다. 개인 앱이라 그 비용을 지불할 이유가 없다. 나중에 추가하려면 토큰이
한 곳(`packages/shared/theme.ts`)이니 이전 부담도 작다.

### 아이콘 — Ionicons 만

`@expo/vector-icons` 의 Ionicons 만 쓴다. **이모지 금지** — 기기·OS 버전마다 렌더링이 달라
디자인이 깨진다.

## 1. 색상 팔레트 (Color Tokens)

### 메인 / 포인트
| 토큰 | 값 | 용도 |
|------|-----|------|
| primary | `#3182F6` | 메인 파랑(토스 톤). 주요 버튼, 강조, 활성 상태 |
| primaryPressed | `#1B64DA` | 버튼 눌림 |
| primaryLight | `#E8F1FD` | **선택된 영역의 배경** (세그먼트 칸 등) |

### 무채색 (기반)
| 토큰 | 값 | 용도 |
|------|-----|------|
| background | `#FFFFFF` | **카드·모달·탭 바** 표면 |
| surface | `#F9FAFB` | **화면 배경**, 카드 안 선택 영역 바탕 |
| border | `#E5E8EB` | 옅은 divider(카드 내부 칸 구분) |
| borderStrong | `#D1D6DB` | 진한 구분선 — **탭 바 상단 한 줄 전용** |
| textStrong | `#191F28` | 제목, 강조 텍스트 |
| textNormal | `#4E5968` | 본문 |
| textAlt | `#8B95A1` | 보조/설명 텍스트 |
| textDisabled | `#C9CDD2` | 비활성 |

> ⚠️ **`background`(흰색)와 `surface`(연회색)의 용도가 이름과 반대다.**
> **화면 배경이 `surface`, 카드가 `background`** 다. 처음엔 이름대로 화면을 흰색으로 뒀는데
> 카드·탭 바까지 전부 흰색이라 **아무것도 구분되지 않았다.** 어드민에서도 같은 문제를 겪고
> 같은 방식으로 고쳤다("흰 배경에 흰 카드 금지").
>
> ⚠️ `borderStrong` 은 **5장의 무테두리 원칙보다 먼저 만든 토큰**이다. 지금은 탭 바 상단처럼
> **선 한 줄이 필요한 자리**에만 남긴다. 새 컴포넌트에 테두리 용도로 쓰지 말 것.
> `textDisabled` 를 테두리로 쓰는 것도 금지 — 의미가 어긋나고 그 값을 조정하면 선이 같이 변한다.

### 상태색
| 토큰 | 값 | 용도 |
|------|-----|------|
| success | `#00B26E` | 적중, 성공 |
| successLight | `#E5F7EF` | **적중 영역의 배경** (적중한 세그먼트 칸, 어제 결과 배너) |
| danger | `#F04452` | 실패, 경고, 파괴적 동작(회원 탈퇴 등) |
| warning | `#FFB020` | 집계중 등 대기 상태 |

> ⚠️ **포인트 차감에 `danger` 를 쓰지 않는다.** 뽑기로 포인트를 쓰는 것은 실패가 아니라
> 정상 행동이라, 내역이 빨간 줄로 가득하면 잘못한 것처럼 보인다. 차감은 `textNormal` +
> 부호(`−`)로 쓰고 **획득만** `success` 로 강조한다.
>
> 강조는 **글자색 + 옅은 배경**으로 한다. `success` 를 배경에 꽉 채웠더니 너무 진해서
> 배너가 버튼처럼 보였다. `*Light` 는 `primaryLight` 와 같은 농도로 맞춰 뒀다.

### 카드 등급색 (등급 표현 전용 — UI 포인트 컬러와 구분)
| 등급 | 토큰 | 값 |
|------|------|-----|
| 일반 N | gradeNormal | `#8B95A1` (회색) |
| 레어 R | gradeRare | `#4A90D9` (등급용 파랑 — primary보다 차분) |
| 에픽 E | gradeEpic | `#9B51E0` (보라) |
| 레전드 L | gradeLegend | `#F2A900` (금) |
| 신화 M | gradeMythic | `#E03131` (빨강) |

> 주의: 등급색은 **카드·등급 표시에만** 사용. 일반 UI(버튼 등)엔 primary만.

## 2. 타이포그래피 (Type Scale)

| 토큰 | 크기/굵기 | 용도 |
|------|----------|------|
| display | 32 / Bold | 포인트 잔액, 큰 숫자 강조 |
| title1 | 24 / Bold | 화면 제목 |
| title2 | 20 / Bold | 섹션 제목 |
| body1 | 16 / Regular | 기본 본문 |
| body2 | 14 / Regular | 보조 본문 |
| caption | 12 / Regular | 설명, 라벨 |
| button | 16 / SemiBold | 버튼 텍스트 |
| buttonSmall | 13 / SemiBold | 카드 안 보조 버튼(헤더 우측 알약 등) |

- 폰트: **Pretendard 확정.** 파일은 `packages/assets/fonts/pretendard/native/*.otf` (Regular/SemiBold/Bold 3종).
  - ⚠️ **커스텀 폰트에 `fontWeight` 를 같이 주면 시스템 폰트로 폴백된다.** 굵기별 파일이
    별도 패밀리로 등록되기 때문이다. 굵기는 **패밀리 이름으로만** 지정한다.
  - 그래서 화면에서 `react-native` 의 `Text` 를 직접 쓰지 않고 `components/ui/Text.tsx` 를 쓴다
    (토큰 → 패밀리 변환을 거기서 한 번만 처리).
- 숫자 강조 시 tabular-nums 사용(자릿수 흔들림 방지).

## 5. 그림자 (Shadow) — **테두리 대신 그림자를 쓴다**

- 은은하게. 진한 그림자 금지.
- 카드: `y=2, blur=8, rgba(0,0,0,0.06)` 수준.
- 떠 있는 버튼(FAB 등): 약간 더 강하게.

### ⚠️ 테두리는 쓰지 않는다 (전 화면 원칙)

**`borderWidth` 를 쓰지 않는다.** 카드·컨테이너·버튼·선택 영역 전부 해당한다.

처음엔 카드에 테두리를 두고 그 안의 선택 영역에도 테두리를 뒀더니 **"액자 안의 액자"**
가 되어 정신사납고 정돈이 안 된 느낌이 났다(실제로 그렇게 보였다). 테두리를 없애고
그림자만 남기니 훨씬 깔끔해졌다.

구분이 필요할 때의 우선순위:

1. **여백** — 가장 먼저 고려한다
2. **배경 계층** — 회색 화면(`surface`) 위 흰 카드(`background`), 또는 그 반대
3. **그림자** — 떠 있는 느낌이 필요할 때
4. **얇은 divider** — 같은 덩어리 **안**을 나눌 때만. `border` 색, 별도 `View` 로 둔다
   (테두리로 그리면 조건부로 숨길 수 없다)

**선택·강조도 테두리로 표시하지 않는다.** 옅은 배경(`primaryLight` / `successLight`) +
글자색으로만 알린다. 선택된 칸에만 테두리를 둬도 결국 선이 한 겹 더 생겨 산만해진다.

유일한 예외는 **화면 영역을 나누는 선 한 줄**(탭 바 상단)이고, 여기에만 `borderStrong` 을
쓴다 — 이 원칙을 세우기 전에 만든 토큰이라 남아 있는 것이다.

## 6. 컴포넌트 스타일

### 버튼
- 메인 버튼: 배경 primary, 텍스트 흰색, radius md, 폭 넓게.
- 눌림 시 primaryPressed + 살짝 scale(0.98) 애니메이션.
- 보조 버튼: 배경 surface, 텍스트 textNormal. **테두리 없음.**
- 크기 3종:

| size | 높이 | 텍스트 | 쓰는 곳 |
|------|-----|--------|---------|
| default | 52 | button | 화면 하단 주요 동작 |
| compact | 36 | button | 카드 안 주요 동작 |
| small | 28 | buttonSmall | **카드 헤더의 남은 공간** — 버튼 때문에 카드가 커지면 안 되는 자리 |

- `small` 은 최소 터치 영역(44)보다 작으므로 **`hitSlop`** 으로 레이아웃 없이 영역만 넓힌다.
- `pill`(radius full)은 폭을 내용만큼만 쓴다. `flexDirection: 'row'` 컨테이너 안에 둬야 한다.

### 카드(경기·수집 카드 등 UI 컨테이너)
- 배경 `background`(흰색), radius lg, **은은한 그림자만**, 내부 패딩 md.
- ⚠️ 카드 높이가 상태에 따라 **늘었다 줄었다** 하지 않게 한다. 조건부로 나타나는 버튼은
  들어갈 행에 `minHeight` 를 걸어 자리를 미리 잡아둔다.

### 강조 카드 (요약 카드 등)
- 한 카드를 눈에 띄게 하려면 **카드 배경을 `primaryLight`** 로 두고, 그 안의 블록은
  **흰색(`background`)으로 반전**한다. 회색 화면 위에서 떠 보이면서 진하지 않다.
- ⚠️ **흰 카드 안에 파란 블록을 넣는 방식은 쓰지 않는다** — 카드 안에 파란 블록 + 회색
  블록으로 층이 두 겹이 되어 산만해진다. 강조는 **배경색 한 겹**으로만 한다.
- 옅은 파랑 위의 보조 문구는 `textAlt` 대신 **`textNormal`** — 대비가 모자라 흐려 보인다.

### 세그먼트 선택 (경기 카드의 원정 / 무승부 / 홈)
- `surface` 회색 **한 덩어리** 안에 칸을 나란히 두고, 칸 사이는 **얇은 divider** 로만 구분한다.
- 칸 최소 높이 44. 무승부 칸만 **고정 폭 76**(두 자리 스코어까지) + 작은 글씨 —
  팀 칸과 같은 폭이면 가운데가 과해 보인다.
- 팀 칸은 마크(18) + 팀명을 **가로**로, 좌우 **거울 배치**, 내용은 **바깥쪽 끝**에 붙인다.
  가운데 정렬하면 세 칸이 안쪽으로 뭉쳐 보인다.
- 선택 = `primaryLight` 배경 + primary 글자. 적중 = `successLight` 배경 + success 글자.
  **채워진 칸 양옆 divider 는 숨긴다** — 색이 찬 칸에 선이 붙으면 칸이 잘려 보인다.
- 눌림 피드백은 **배경색 변화**. `scale` 을 쓰면 폭이 넓은 칸에서 위아래에 틈이 생겨 깜빡인다.

### 상태 표시
- **알약 배지를 쓰지 않는다.** 시각·상태를 `18:30 | 5시간 남음` 한 줄로 모으고 강조는
  **글자색**(primary / danger / warning / textAlt)으로만 한다. 오른쪽 위에 색 알약이 뜨면
  본문과 경쟁해 시선이 갈린다.
- 한 줄 안에서도 **위계를 준다**: 시각만 `button`(16), 뒤따르는 상태는 `caption`(12).
  같은 크기면 남은 시간이 시각만큼 커 보여 무엇이 경기 시간인지 한눈에 안 잡힌다.
- 인라인 구분자는 **`|` 글자**(`caption` / `textDisabled`). 1px `View` 를 쓰지 않는다 —
  글자는 baseline 에 저절로 맞지만 View 는 높이·수직 위치를 손으로 맞춰야 하고
  폰트 크기를 바꿀 때마다 다시 어긋난다.
- 색 의미: 적중 success / 실패·임박 danger / 집계중 warning / 마감·종료 textAlt.
- 결과가 이미 다른 요소로 드러났다면(예: 적중한 칸이 초록) **다시 강조하지 않는다.**

## 7. 애니메이션 (react-native-reanimated)

- 화면 전환: 부드러운 슬라이드/페이드.
- 버튼 탭: scale 0.98 + 살짝 눌리는 피드백.
- 숫자 변화(포인트 획득/차감): 카운트업/다운 애니메이션.
- 과하지 않게. 빠르고(200~300ms) 자연스럽게.

### 7.1 뽑기 연출 (확정) — 카드팩 개봉

> **의도된 예외.** 이 화면만 화려하다. 홈·도감·마이는 심심하게 두고 **드라마를 여기 한 곳에
> 몰아넣는다.** 다른 화면도 화려하게 만들면 토스 감성이 깨지고 뽑기의 임팩트도 죽는다.
> "왜 뽑기만 다르냐"는 질문의 답이 이것이다.

레퍼런스: 포켓몬 TCG Pocket 팩 개봉.

**① 팩 선택** — 구현됨(`app/(tabs)/draw.tsx`)

- **일반·프리미엄 팩을 나란히** 놓는다 — 뽑기 종류 선택과 팩 선택을 두 단계로 나누지
  않는다(한 화면 한 행동).
- 포인트 부족한 팩은 흐리게 + 자물쇠 + "포인트 부족". 누를 수 없다 —
  눌러서 실패를 알리는 방식은 택하지 않았다(눌러 보기 전에 알아야 한다).
- 보유 포인트는 상단에 `display`(32/Bold)로 시원하게.
- 등급 확률은 **접었다 펴는 표**로 화면 안에서 끝낸다. 일반·프리미엄을 한 표에 나란히 둬서
  프리미엄이 무엇이 좋은지 두 표를 번갈아 보지 않고 안다.

⚠️ **캐러셀·바닥 반사는 넣지 않았다.** 종류가 **둘뿐**이라 캐러셀이면 한 번에 하나만 보여
비교가 안 되고, 스와이프해야 프리미엄이 있다는 걸 알게 된다. 나란히 두면 그 문제가 없다.
반사는 종류가 늘어 캐러셀로 바꿀 때 함께 검토한다.

**② 개봉 — 스와이프로 자르기**

자동 재생이 아니라 **유저 제스처**로 자른다. 촉각적 참여가 긴장감을 만든다.

상태는 `choose → ready → cutting → revealed` 네 단계다.

| 순서 | 연출 | 시간 |
| ---- | ---- | ---- |
| 1 | 장수(1장/10장)를 고르면 **팩이 1.12배로 확대** + 절단선 등장 | spring |
| 2 | 절단선을 **가로질러 스와이프** → 궤적을 따라 선이 자란다(폭의 60% 넘기면 절단) | 제스처 |
| 3 | 상단부가 −6° 젖혀졌다가 20°까지 회전하며 날아감 + 절단면에서 빛 + 화면 플래시 | 760ms |
| 4 | 하단부가 **마지막에** 아래로 빠지며 사라짐 | 위 구간 후반 |
| 5 | 카드가 아래에서 솟아오름(scale 0.88 → 1) | 300ms |

- ⚠️ **`cutting` 단계가 반드시 필요하다.** 자르고 바로 결과로 넘기면 팩이 언마운트되면서
  **상단이 날아가는 것을 볼 수 없다**(그렇게 만들었다가 고쳤다).
- ⚠️ **하단부를 먼저 없애지 말 것** — 무엇이 잘렸는지 알 수 없어진다.
- ⚠️ **절단선은 잘리는 순간 즉시 사라져야 한다.** 남겨 두면 벌어진 틈에 선이 떠 있어
  아직 안 잘린 것처럼 보인다.
- ⚠️ **하단 버튼 영역에 `minHeight`** 를 걸어 둔다. 단계마다 버튼 수가 달라 높이가 변하면
  절단 중에 팩이 위아래로 흔들린다.
- 등급 글로우·**L·M 스파클은 미구현**(에셋 없음, 7.3 참고). Haptics 도 미설치.
- 중복 카드: 우상단 **"보유" 배지**. 포인트 카운트업은 없다 — 자동 환급을 폐지했고
  하단의 `여분 N장 판매` 버튼을 눌러야 들어온다(통합기획서 6장).

**③ 10장 뽑기 — 팩 하나, 카드는 한 장씩**

- 팩은 **하나만** 자른다(10개를 깔지 않는다). 자르는 행위를 열 번 반복하지 않으므로
  "짧고 시원하게" 는 그대로 지킨다.
- 카드는 **한 장씩 탭해서 넘긴다.** `3 / 10` 카운터와 "탭해서 다음 카드" 안내를 둔다.
- **최고 등급을 마지막 순서로 배치**해 클라이맥스를 만든다. 뽑기 결과 자체는 서버가 정하고
  클라이언트는 **공개 순서만** 바꾼다.
- ⚠️ **마지막 장까지 보기 전에는 `한 번 더`·닫기(X)를 감춘다.** 포인트는 이미 빠졌는데
  실수로 나가면 결과를 되돌려 볼 방법이 없다.

⚠️ **격자로 한 번에 깔지 말 것.** 그렇게 만들었다가 걷어냈다 — 카드가 작아져 등급색밖에
안 보이고 **무엇을 뽑았는지 한 장도 제대로 못 본다.** 결과 요약표처럼 읽혔다.

**④ Haptics** (`expo-haptics`)

| 등급 | 피드백 |
| ---- | ------ |
| N · R | light |
| E | medium |
| L | heavy |
| M | success 알림 + 연속 진동 |

### 7.2 구현 방침 — 3D 없이 2D 로 근사

포켓몬은 실제 3D지만 우리는 2D 로 만든다. 훨씬 가볍다.

⚠️ **개봉 연출은 RN 코어 `Animated` + `PanResponder` 로 만들었다**(reanimated 아님).
이 정도 연출은 코어로 충분하고 `useNativeDriver` 로 scale·opacity·translate 가 전부
네이티브에서 돈다. reanimated 4 는 worklet 런타임을 거치는데 그만한 이유가 없었다.
reanimated 는 설치돼 있으니 더 복잡한 연출이 필요해지면 그때 쓴다.

⚠️ **폭을 애니메이션하지 말 것.** 절단선을 `width` 로 늘리면 매 프레임 JS 를 거쳐 끊긴다.
**`scaleX` + `transformOrigin: 'left'`** 로 늘린다(네이티브 드라이버로 돈다).

| 연출 | 구현 |
| ---- | ---- |
| 팩 입체감 | 미리 렌더된 이미지 + skew · 그림자 |
| 캐러셀 | reanimated + gesture-handler |
| 자르기 | **팩 이미지를 상단/하단 2장으로 분리 준비** → 스와이프 후 상단만 이동(마스크 불필요) |
| 빛 방사 | 방사형 그라디언트 PNG 를 rotate + scale + opacity |
| 스파클 | 파티클은 무겁다 → 스프라이트 2~3장 랜덤 배치 |

### 7.3 필요 에셋

| 에셋 | 수량 | 상태 |
| ---- | ---- | ---- |
| 팩 이미지 (일반) | 2장 | ✅ `assets/packs/pack-normal-{top,body}.webp` |
| 팩 이미지 (프리미엄) | 2장 | ✅ `assets/packs/pack-premium-{top,body}.webp` |
| 방사형 빛 | 1장 | ⬜ 없음 — 지금은 **흰 원 + 가로 띠**로 근사(`Burst`) |
| 스파클 | 2~3장 | ⬜ 없음 — L·M 등급 오버레이 미구현 |
| 앱 아이콘 · 스플래시 | 2장 | ✅ 뽑기 탭 `sparkles` 글리프로 생성 |

생성 프롬프트는 `03_카드프롬프트가이드.md` 에 카드와 함께 관리한다.

에셋이 들어오면 `components/draw/` 의 `Burst` 만 이미지로 바꾸면 된다 — 개봉 화면의
다른 코드는 손댈 필요가 없다.

**미결**

- **카드 프레임 레이아웃** — 통이미지 위에 코드로 올릴 이름·도감번호·등급 배지의 위치·크기.
  지금은 `components/draw/CardFace.tsx` 가 등급색 프레임 + 하단 캡션으로 임시 배치했다.
  등록된 카드가 한 장도 없어 실제 이미지로 검증하지 못했다.
- **`expo-haptics` 미설치** — 7.1 ④ 의 등급별 진동이 없다. 의존성 추가 전에 확인 필요.

## 8. 화면별 적용 힌트
- **홈(예측)**: 오늘 경기를 큼직한 카드로 세로 나열. 마감 임박은 시간 강조. 한 경기씩 명확히.
- **뽑기**: 보유 포인트를 display 크기로 상단에 시원하게. 뽑기 버튼 큼직. 연출에 집중.
- **도감**: 그리드. 미보유는 회색 실루엣. 등급색으로 희소도 표현. 진행률 바.
- **마이**: 성적/포인트를 숫자 위주로 깔끔하게.

## 9. 금지 사항
- 화면마다 다른 색/폰트/여백 즉흥 사용 금지 → 반드시 토큰 참조.
- 등급색을 일반 UI에 남용 금지.
- 진한 그림자, 과한 애니메이션, 좁은 여백 금지(토스 감성 해침).
- **이모지 금지** — Ionicons 만 쓴다(기기별 렌더링 불일치).
- 커스텀 폰트에 `fontWeight` 지정 금지 — 시스템 폰트로 폴백된다(2장 참조).
- **`borderWidth` 금지**(탭 바 상단선 예외) — 선택 상태도 배경 틴트로만 표시한다(5장 참조).
- 알약 배지 금지 — 상태는 글자색으로 알린다(6장 참조).
- **뽑기 화면의 화려함을 다른 화면으로 가져오지 말 것.** 7.1 의 예외는 뽑기 전용이다.
